# Keeper scan — LLM judge false-accept check (PILOT)

**Date:** 2026-08-15
**Data:** `data/sft/traces_claude_validation_judged.jsonl` (18 traces, 14 keepers)
**Presenter:** `scripts/eval/build_keeper_scan.py` → `results/analysis/keeper_scan.html`
**Scanned by:** Claude (cross-check) — **NOT an independent human audit**

---

## What this is, and what it is not

This is a **PILOT keeper scan**: a fast pass over every row the LLM judge
accepted, asking one question per row — *does the teacher's ANSWER correctly
identify a person of the GROUND TRUTH?*

It checks for **false accepts only**. That is deliberate. For a pilot, the only
judge error that damages training *data* is a false accept (a wrong identity
waved into the SFT set); a false reject costs yield, which the 2× scenario-
generation plan already absorbs. Every false accept lives in the keepers, so
scanning the keepers is the complete check for the error that matters.

**This is NOT the rigorous 30-label precision/recall audit.** That audit needs
the rejects too, a blind protocol, and an annotator who is not the system under
test. It is **DEFERRED to just before the final scaled run.**

### Provenance caveat — read this before citing the result

**The scan was performed by Claude, cross-checking a judge that is also Claude.**
Teacher, judge, and scanner are all the same model family. A shared blind spot
is therefore **not excluded by this result** — it is exactly the failure mode the
audit exists to rule out, and a same-family cross-check cannot rule it out.

What this scan can catch: **gross** false accepts (an answer that plainly names a
different kind of person than the ground truth). What it cannot catch: an error
the judge and the scanner make *together*.

The repo has a precedent for trusting an unaudited instrument — `t_think_07`,
which ran at precision **0.185** while looking healthy. The deferred 30-label
audit must use a **human or a non-Claude model** to be worth anything.

## Result

| | |
|---|---|
| Keepers scanned | **14 of 18** |
| Gross false accepts | **0** |
| Borderline, noted not dropped | **1** (scenario id 13) |
| Verdict | **Keeper precision good enough for a PILOT** |

All 14 keepers are correct identifications.

### Coarser matches — intended judge behaviour, not errors

Four keepers give an answer coarser than the seed label. The judge's rubric
permits coarser answers and forbids contradictory ones, so these are the rubric
working as written:

| id | ground truth | answer | reading |
|---|---|---|---|
| 0 | a retired sergeant of the Royal Marines | "a former soldier turned commissionaire" | correct, coarser rank/branch |
| 3 | a professional concert violinist | "a violinist" | correct, drops "concert" |
| 5 | a deep-sea trawler fisherman | "a merchant seaman or trawler hand" | correct, offers trawler hand |
| 7 | a medical student in the week before finals | "a university student cramming … medical examination" | correct, coarser field |

### The one borderline — id 13 (NOTED, not dropped)

- **Ground truth:** someone who has recently emigrated from a hot country to a cold one
- **Answer:** "a woman newly **returned** from months of outdoor manual labor in a hot foreign country…"

Correct on the *situation* (recently arrived in a cold climate from a hot one,
not yet readjusted) but it slips **emigrant vs returnee** — a different life
story from the same cues. Not counted as a false accept because the deducible
content is right and the distinction is not recoverable from the cues.

It is also **already excluded by the other gate**: id 13 is one of the six
scenarios the disambiguation check flagged AMBIGUOUS, so it never reaches the
SFT set regardless of the judge's verdict.

## Incidental observation — the two gates overlap on the soft rows

Of the 14 keepers, **5 sit on scenarios the disambiguation check independently
flagged AMBIGUOUS** (ids 3, 5, 7, 8, 13). After both gates the usable set is
**9 of 18 (50%)** — ids 0, 1, 2, 4, 6, 9, 12, 15, 16 — which reproduces the
combined yield recorded in the Decision Log on 2026-08-15.

Four of the five rows flagged in this scan as coarse-or-borderline (3, 5, 7, 13)
are exactly scenarios the disambiguation check had already flagged. That is a
mild convergent-validity signal for the disambiguation check — the rows a reader
finds fuzzy are largely the rows whose *cues* were measured fuzzy. **Stated as an
observation, not a finding:** n=5, one coarse row (id 0) was not ambiguous, and
the scan was not blind to anything, so this is a pattern worth re-checking at
scale, not a validated property.

## Consequence

- **The judge's keeper gate is cleared for the PILOT.** Scaling scenario
  generation is unblocked for the next session.
- **No rubric change.** Zero false accepts means there is nothing to tighten, and
  tuning `JUDGE_SYSTEM` against this same 18-row set would fit the instrument to
  its own test set — the `t_think_07` lesson, and the standing reason the repo
  refused to loosen `answer_matches` to recover its near-misses.
- **Still outstanding:** the rigorous **30-label independent audit** (human or
  non-Claude annotator, rejects included, blind), required **before the final
  scaled run**. This scan does not substitute for it and does not reduce its
  scope.
- Plan scenario generation at **~2× the target SFT count** — combined yield is
  50%, unchanged by this scan.
